# Smart Brief Engine — מנוע בריפים חכם

**תאריך:** 2026-08-13 · **סטטוס:** מאושר ע"י המשתמש (היברידי, כל גל 1)

## מטרה

להפוך את בריפי הסושיאל (יוצרת תוכן, טיקטוק, פוסטים וסטוריז, באנרים) ממסמכי
Google Docs שמעתיקים ידנית — לזרימה מקוונת אחת עם AI, **כאופציה נוספת לצד
המסמכים הקיימים** (לא מחליף אותם). מנוע אחד גנרי; כל בריף נוסף = קובץ תבנית.

## חוויית המילוי — היברידית

1. **הקשר:** העובד בוחר תבנית, מזין שם לקוח (עם השלמה מ-`client_folders`)
   ומתאר בחופשיות את הקמפיין / מדביק חומרים.
2. **טיוטת AI:** המנוע שולף הקשר קיים על הלקוח (פגישת ההתנעה, בריף הלקוח
   שמולא) וקורא ל-`callAI` (ראוטר Gemini/Claude/OpenAI הקיים) לבניית טיוטה
   מלאה בכל שדות התבנית.
3. **טופס:** רנדרר גנרי מציג את השדות עם ערכי הטיוטה. לכל שדה כפתור
   "שפר ניסוח"; פאנל "בדוק חוסרים" מסמן שדות חסרים/חלשים.
4. **שליחה:** תצוגה מקדימה מעוצבת + קישור ציבורי לנמען (יוצרת תוכן / מעצב)
   עם מעקב נפתח.

## ארכיטקטורה

- **תבניות** — `src/lib/smart-brief/templates/*.ts`: רג'יסטרי TS (לא DB) —
  כמו `client-brief/formSteps.ts`. סוגי שדות: text / textarea / list / select
  / date. הוספת בריף = קובץ קונפיג חדש.
- **DB** — טבלה אחת `smart_briefs` (template_slug, client_name, fields jsonb,
  status draft→sent, share_token, opened_at). ללא נגיעה בטבלאות קיימות.
- **API** — `/api/smart-brief` (CRUD), `/api/smart-brief/generate` (טיוטת AI
  מהקשר), `/api/smart-brief/assist` (שיפור ניסוח / חוסרים),
  `/api/smart-brief/[id]/send` (הנפקת קישור).
  אימות עובדים: `getAuthenticatedUser`; כתיבה ב-service-role.
- **UI** — `/smart-brief` (בחירת תבנית + הבריפים שלי),
  `/smart-brief/[id]` (העורך ההיברידי).
  נמען: `/forms/brief/[token]` — ציבורי (תחת `/forms`), קריאה בלבד, מעדכן
  `opened_at`.
- **ספרייה** — `LibraryDoc` מקבל `onlineUrl` אופציונלי: שורת הבריף שומרת את
  קישור ה-Google Doc **וגם** כפתור "מילוי מקוון". `/smart-brief` נוסף
  ל-middleware המוגן.

## מחוץ לסקופ (בכוונה)

אינטגרציה לפיד ההאב, PDF, תבניות ב-DB עם מסך ניהול, סיכום שבועי — גל 2.
